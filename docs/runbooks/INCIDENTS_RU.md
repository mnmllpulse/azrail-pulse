# Аварии

Этап 42. Это порядок действий по тому, что код уже делает. Команды ниже не выкладывают worker, не применяют миграции на `azrail-db` и не восстанавливают боевую или staging базу. `npm run deploy` и `deploy:production` завершаются кодом 2.

Секреты в чат, в исходники и в квитанции не вставлять. Новое значение ключа задаётся только `wrangler secret put`.

## Падение провайдера

Музыкальный генератор на ответ 429, 500 или обрыв сети помечает задачу `failed` и отдаёт ошибку. Тот же бриф после этого можно отправить ещё раз: уйдёт один новый вызов. Пока задача в статусе `running` и младше 15 минут, второй платный запуск не отправляется, ответ 409.

Дневной потолок чата отвечает 429 с кодом `chat_daily_limit`. При `UNIFIED_LEDGER=true` вызов провайдера сначала берёт резерв на сутки `platform:ГГГГ-ММ-ДД`. Если исход неизвестен, резерв остаётся. Если фактический расход больше резерва, лимит этого scope становится 0, пока его не сверят.

На бою `UNIFIED_LEDGER` не включён, `AZRAIL_METERING` стоит `observe`. Отдельного выключателя одного провайдера нет. `AZRAIL_FORCE_FREE` из этой инструкции не переключать.

## D1

`GET /health` с действующим ключом делает `SELECT 1`. Если D1 не отвечает, статус `degraded` и HTTP 503. Если сама запись квоты падает, запрос не пропускается.

`azrail-db`, `azrail-db-staging` и `azrail-pulse-db` этой инструкцией не изменять. Учебное восстановление — `npm run backup:restore:drill`: одноразовая база `azrail-restore-drill-d1-*`, затем удаление. Боевые строки так не возвращаются. RPO и RTO не назначены.

## R2

`GET /health` вызывает `head` на `__healthcheck__`. Ошибка R2 даёт 503, даже если D1 при этом жива. В локальном круге порча файла отклоняется до записи в цель.

Бакеты `azrail-artifacts`, `azrail-artifacts-staging` и `azrail-pulse-artifacts` не удалять. Одноразовый бакет drill имеет имя `azrail-restore-drill-r2-*` и после проверки удаляется.

## Сбой OIDC

При `AUTH_MODE=oidc` запрос без сессии получает 401 «Войдите в аккаунт.» Проверка токена базу не читает. Роль admin даётся только группе из `OIDC_ADMIN_GROUPS`. Пустой список групп admin снимает.

На бою `AUTH_MODE=oidc` не выставлен. Client id и issuer staging в бой из этой инструкции не копировать. Боевые настройки не менять, пока этап 44 держит NO DEPLOY.

## Скомпрометированный ключ

Чужой или утёкший ключ аккаунта гасится так: администратор отправляет `POST /api/admin/accounts/revoke` с `accountId`. Строка получает `disabled=1`. Отключённый аккаунт больше не входит. Истёкший ключ отвечает 401 «Ключ истёк или отозван.»

`AZRAIL_TOKEN` на бою остаётся, пока вход по OIDC не проверен отдельно. Снимать его раньше нельзя. Новое значение не писать в репозиторий. `ELEVENLABS_API_KEY` хранится секретом worker, не в чате.

## Аномалия счёта

Дневной потолок провайдера берётся из `DAILY_PROVIDER_CALLS`, иначе 200, и только когда `UNIFIED_LEDGER=true`. Час квоты — отдельное окно. Нулевой настроенный лимит блокирует бюджет, а не возвращает запасной потолок.

Если списание превысило резерв, лимит этого scope обнуляется. Это стоп дальнейших вызовов scope, не стоп одного провайдера и не выключение `AZRAIL_FORCE_FREE`. На бою ledger выключен, поэтому этот стоп там сейчас не работает.

## Плохой выклад

Новый выклад не запускать. Решение канарейки: доли 1, 5, 25, 50, 100. Выше доля 5xx, ошибок входа, срывов задач или задержки против предыдущего артефакта — откатить worker. Откат базу не восстанавливает. Живой доли трафика нет, на бою автоматический откат не включён. Старый id выклада из контракта релиза целью отката не брать.

## Блокировка пользователя

Нужно закрыть вход одному аккаунту — `POST /api/admin/accounts/revoke`. Поле `disabled=1`. Сессии OIDC с отключённым аккаунтом не проходят. Это не удаляет проекты и не трогает D1 целиком.

## Затор задач

Музыкальная задача моложе 15 минут в статусе `running` держит повтор. После `failed` повтор разрешён и снова один. Очереди, которая дописывает музыку после закрытия вкладки, нет. Пока живого прогона долгих задач нет, квитанцию `VERIFIED` для них не писать.

## Восстановление данных
