# Правила ведения документации

Status: current

1. Истина по порядку: код, `scripts/`, `config/`, затем `docs/current/` и `docs/runbooks/`. История не источник.
2. Каждый файл в `docs/current/` начинается с `Status: current` или `Status: snapshot YYYY-MM-DD`.
3. Snapshot живёт не дольше релиза: при выходе RC уходит в `docs/history/`, а в `docs/history/CHANGELOG_ARCHIVE.md` добавляется одна строка.
4. Журналы, логи, скриншоты и сырой вывод проверок в репозиторий не кладём. Они остаются в CI-артефактах.
5. Один факт — один файл. Дубли заменяем ссылкой.
6. Новая архитектура заменяет старую в том же файле. Прежний вариант хранит история git.
7. Полный архив до чистки 2026-11: ветка `archive/docs-2026-11`.
8. После правки документации: `npm run source:manifest`, `npm test`, `npm run repo:hygiene`.
9. Строки, которые проверяет `scripts/check-doc-truth.mjs`, не удаляем без правки гейта в том же PR.
10. Для ИИ-ассистента: сначала `docs/current/`, `docs/runbooks/`, код. `docs/history/` читаем только по прямой просьбе.
