# Локальный агент

Status: active

Агент даёт AZRAIL доступ к одной папке на твоём компьютере. Без него воркер в облаке не видит твои файлы.

## Принципы

| Правило | Как соблюдается |
|---|---|
| Выключен по умолчанию | Состояния нет, пока владелец не нажмёт «Включить» в настройках |
| Короткая сессия | Ключ действует 1 час, повторное включение отзывает прежний ключ |
| Одна папка | Агент работает от `AZRAIL_ROOT`, пути вне неё и симлинки наружу отклоняются |
| Секреты закрыты | `.env*`, `.dev.vars`, `.git`, `.ssh`, `node_modules`, `*.pem`, `*.key` не читаются и не пишутся (сервер и агент проверяют независимо) |
| Запись по подтверждению | `write` ждёт «Разрешить» владельца; `read` и `list` идут сразу |
| Команды из белого списка | `run` принимает только идентификатор: `git_status`, `git_diff`, `git_log`, `node_version`, `npm_test`, `npm_build`, `npm_lint`, `npm_typecheck`. Аргументы зафиксированы в агенте, оболочки нет, лимит 2 минуты, каждый запуск ждёт «Разрешить». Дочерний процесс не получает `AZRAIL_*`. Произвольных команд нет |
| Страницы под твоими входами | `web` читает страницу в браузере компьютера (Chrome через playwright) и идёт сразу, как `read`. Только чтение: кликов и ввода нет. Адреса проверяются на сервере и в агенте одинаково: только публичные http(s), без логина в адресе, портов, внутренних имён и частных IP; редирект и подзапросы на внутренние адреса блокируются |
| Только владелец | Все владельческие маршруты требуют роль admin |

## Запуск

1. Настройки → «Агент на компьютере» → «Включить на 1 час».
2. Скопируй показанные строки в PowerShell, указав свою папку в `AZRAIL_ROOT`.
3. Агент пишет в консоль каждое действие. Остановка: Ctrl+C или «Выключить».

## API

Владелец: `GET /api/agent/status`, `POST /api/agent/enable`, `POST /api/agent/disable`, `POST /api/agent/jobs`, `GET /api/agent/jobs/:id`, `POST /api/agent/jobs/:id/approve|reject`.
Агент (Bearer `azagent_…`): `GET /api/agent/poll`, `POST /api/agent/jobs/:id/result`.

Очередь хранится в SQLite объекта Orchestrator (экземпляр `local-agent`), миграции D1 не нужны. Задачи живут 15 минут.

## Ограничения

- Из чата задачи ставятся только по явной фразе с «на компьютере» или «в папке»: «прочитай src/a.ts на компьютере», «покажи файлы в src на компьютере», «запиши в notes/a.txt на компьютере:» и текст со следующей строки. Запись и запуск команд ждут ответа «разреши» или «отклони». Фразы для команд: «запусти тесты на компьютере», «собери проект на компьютере», «покажи git status на компьютере». Если агент выключен, чат говорит об этом и ничего не ставит.
- Место распознаётся и в разговорной форме: «на компьютере/компе/пк/ноуте», «на локальном компе», «на моей машине», «локально». Глаголы запуска: запусти, прогони, выполни, сделай, проведи, проверь («сделай тест на локальном компе» = npm test).
- Просьба про компьютер, которую чат не распознал («запусти докер на компе»), получает подсказку со списком фраз, а не ответ модели «доступа нет». Запрос к агенту при этом не создаётся.
- Цикл исправления: «исправь ошибки сборки на компьютере» или «почини тесты на компьютере». Чат один раз просит «разреши» (принимаются также «ок», «да», кавычки). После этого до 3 раундов: запуск → разбор лога → правка → повторный запуск. Правятся только файлы, названные в логе и прочитанные агентом, не больше 3 за раунд; закрытые пути агент отклоняет сам. Перед записью оригинал копируется в `.azrail-backup/rN/` (каталог в `.gitignore`). Успех — только код выхода 0; при исчерпании раундов или невалидном ответе модели цикл останавливается и показывает хвост лога. Согласие живёт в памяти вкладки и не переживает перезагрузку страницы.
- Откат: «откати правки на компьютере» показывает список файлов последнего цикла и после «разреши» возвращает каждый файл из самой ранней копии в `.azrail-backup/`. Список файлов хранится в localStorage браузера (`azrail.fixRestore.v1`); в другом браузере откат недоступен, копии при этом лежат в папке проекта. Если копия не записалась, файл не меняется.
- Сквозной тест `tests/local-agent-e2e.test.ts`: HTTP-сервер на логике `src/lib/local-agent.ts` и настоящий `azrail-agent.mjs` во временной папке с git-репозиторием. Проверяет чтение, запись с подтверждением, отклонённую запись (файла нет), команды `node_version` и `git_status`, закрытые пути, вставленные в обход сервера (агент сам отказывает), завершение агента после конца сессии. Не проверяет Cloudflare, браузер и модель.
- Панель «Терминал» (кнопка «Код» → вкладка «Терминал»): выбор «Компьютер» запускает команду из белого списка через агента, перед запуском показывает «Разрешить / Отклонить»; выбор «Песочница: тесты» вызывает `/api/trial/sandbox`. Журнал хранится только в открытой вкладке.
- Запуск: после «Включить на 1 час» показывается панель «Запуск на компьютере»: поле папки (пусто = текущая папка PowerShell через `(Get-Location).Path`), готовая команда и кнопка «Скопировать команду». Ключ показывается один раз; после обновления страницы нужно выключить и включить агента заново. Агент в каждом запросе передаёт свою папку в заголовке `X-Agent-Root`, статус возвращает её (`root`), интерфейс показывает «Агент подключён, папка: …» и сам обновляется каждые 3 с, пока агент включён. Абсолютный путь внутри этой папки в форме задачи пересчитывается в относительный, путь вне неё отклоняется до отправки.
- Терминал в «Живом экране» — не PowerShell: цель «Компьютер» запускает только команды из выпадающего списка (белый список агента), произвольный текст вставить нельзя. В шапке виден статус агента и кнопка «Открыть настройки агента»; PowerShell с самим агентом запускается отдельно в Windows.
- Обзор папки при незапущенном агенте показывает 4 шага запуска и кнопку «Повторить».
- Несколько папок: в поле «Папки, которыми сможет управлять агент» укажи пути через `;` (команда запуска выставит `AZRAIL_ROOTS`). Агент называет папки по последнему звену пути (повтор: `-2`, `-3`), не больше 8. При двух и более папках в настройках появляется выбор «Активная папка»: смена применяется сразу, без перезапуска агента; чат, терминал и обзор папки работают в выбранной. Добавить новую папку в список можно только перезапуском агента.
- Задача несёт имя папки (`root`); сервер проверяет его по списку, который сообщил агент. Без `root` задача идёт в первую папку. Ограничения путей (`..`, симлинки, секреты) действуют в каждой папке отдельно.
- Обзор папки (Настройки → «Локальный агент»): проводник по корневой папке агента. Папки, переход вверх, хлебные крошки, просмотр файла (чтение, до 200 000 байт, показ первых 20 000 символов). Клик по записи подставляет путь в форму задачи. Корень задаётся переменной `AZRAIL_ROOT` при запуске агента; выше корня и вне её браузер ничего не показывает, чтобы выбрать другую папку, агента перезапускают с другим `AZRAIL_ROOT`. Команды выбираются из списка белого списка. Задачи обзора не попадают в список последних задач. После действия агент 30 секунд опрашивает очередь каждые 0,7 с (в покое раз в 3 с).
- Перед постановкой команды терминал и чат спрашивают `GET /api/agent/status`: если агент выключен или от него нет сигнала больше 15 секунд (`connected: false`), команда не создаётся, а ответ объясняет, что сделать. Пока агент выполняет команду, он не опрашивает очередь, поэтому вторая команда в это время получит то же сообщение.
- Режим разрешений агентов переключается в ⚙ → «Разрешения агентов» (только admin): «Доверять рабочей папке» (`trusted`) или «Спрашивать всё» (`ask`). Значение хранится в KV и важнее `AZRAIL_PERMISSION_MODE`; при сбое KV действует `ask`. Режим `autonomous` из интерфейса не включается: он ничего не расширяет, уровни 2–3 всегда с подтверждением.
- Защита: ответы агента в чате и запросы модели проходят `redactSecrets`; в цикле исправления файл с секретом или с сигналом подмены инструкций модели не отдаётся (`screenFiles`). Подробности — в модели угроз.
- Чтение — до 200 000 байт, запись — до 200 000 символов.
- Выключатель `AZRAIL_SWITCH_TOOLS=off` закрывает все маршруты агента.
- Страницы под входами: «открой https://сайт в моём браузере» (также «в моём хроме», «под моим входом» или «на компьютере» с полным адресом) ставит задачу `web`. Агент открывает страницу в отдельном профиле `~/.azrail-browser` (папка меняется через `AZRAIL_BROWSER_PROFILE`), не в основном Chrome, и возвращает адрес, заголовок и текст до 20 000 символов. Входы в сайты делаются один раз: `node scripts\local-agent\azrail-agent.mjs --browser-login` открывает обычный Chrome с этим профилем (без управления из программы, иначе Google отказывает во входе), войди и закрой окно. Нужны `npm install` в папке проекта и установленный Google Chrome (другой — `AZRAIL_BROWSER_CHANNEL`). `AZRAIL_BROWSER_HEADED=1` показывает окно при чтении. Клики, ввод и скриншоты на ПК — следующие этапы, каждое действие будет ждать «Разрешить».
- Привязка компьютера (без копирования ключа): агент без `AZRAIL_AGENT_TOKEN` просит привязку (`POST /api/agent/pair/start`), показывает код вида `1234-5678` и ждёт. Владелец вводит код в AZRAIL (`POST /api/agent/pair/approve`), агент получает постоянный ключ `azdev_…` один раз (`POST /api/agent/pair/poll`) и сохраняет его в `~/.azrail-agent.json` (`AZRAIL_DEVICE_FILE` меняет путь). Код живёт 10 минут, после 5 ошибок сгорает, новый запрос не чаще раза в 5 секунд. Один компьютер: новая привязка заменяет прежнюю, `POST /api/agent/pair/forget` отвязывает и выключает доступ. Постоянный ключ сам ничего не открывает: задачи отдаются, только пока открыто окно «Включить на 1 час». Без окна агент отвечает `idle` и ждёт, раз в 5 секунд. Если сервер отвязал компьютер (401), агент стирает файл и предлагает привязку заново. Старый способ (`AZRAIL_AGENT_TOKEN`) работает как прежде.
- Файлы для двойного клика в корне репозитория (PowerShell не нужен): `Start-Azrail-Agent.bat` — запускает агента в своей папке (адрес AZRAIL зашит, переопределяется переменной `AZRAIL_URL`), перед стартом тихо делает `git pull --ff-only`, при первом запуске сам ставит зависимости; `Login-Sites.bat` — один раз войти в сайты в обычном Chrome; `Autostart-On.bat` / `Autostart-Off.bat` — ярлык запуска в автозагрузке Windows (свёрнутое окно). Файлы хранятся с CRLF (`.gitattributes`).
- Порядок для пользователя: двойной клик `Start-Azrail-Agent.bat` → в окне код → «Настройки → Агент на компьютере» → ввести код → «Подтвердить компьютер». Дальше достаточно «Включить на 1 час» в настройках или в карточке чата; ключ копировать не нужно. «Забыть компьютер» отвязывает его.
- Папки без перезапуска: «Настройки → Локальный агент → Папки агента». «Добавить папку» ставит задачу `addroot` (рабочий стол, документы, загрузки — агент сам находит их, включая перенос в OneDrive — или полный путь), задача ждёт «Разрешить добавить папку». «Убрать» ставит `droproot` (последнюю убрать нельзя). Агент не выдаёт: корень диска, домашнюю папку целиком, системные папки (Windows, Program Files, `/etc`, `/usr` и т. п.), папки с секретами и служебными данными (`.ssh`, `.gnupg`, `.aws`, `.git`, `node_modules`, `AppData`, `.azrail*`); ссылка на запрещённое место проверяется по реальному пути. До 8 папок. Добавленные папки запоминаются в `~/.azrail-roots.json` (`AZRAIL_ROOTS_FILE`) и возвращаются после перезапуска; папку, где лежит `.bat`, можно убрать только на текущий запуск.

## Миссии управляют компьютером (шаг 1)

Модель миссии сама вызывает инструменты агента:

| Инструмент | Что делает | Разрешение |
|---|---|---|
| `local_list`, `local_read`, `local_web`, `local_status` | смотреть папки, файлы, сайты под твоими входами | не нужно |
| `local_write`, `local_run`, `local_addroot` | записать файл, команда из белого списка, добавить папку | «Разрешить» в Настройки → Локальный агент |

- Проекту нужно право `local`: POST `/api/admin/permissions` (capability `local`).
- Опасные действия ставят миссию на паузу (`waiting_approval`). Когда агент выполнил задачу или ты её отклонил, миссия продолжается сама.
- Продолжение проверяет статус задачи в очереди агента: пока не `done/failed/rejected/expired` — не продолжает.
- Содержимое с компьютера и сайтов — внешние данные, не инструкции.

## Файлы (шаг 2)

| Инструмент | Что делает | «Разрешить» |
|---|---|---|
| `local_search` | поиск по именам и тексту, до 100 совпадений | нет |
| `local_edit` | заменяет ровно одно вхождение; копия до правки в `.azrail-trash/<время>/` | да |
| `local_mkdir` | создаёт папку | да |
| `local_move` | перенос и переименование, существующее не затирает | да |
| `local_trash` | не удаляет, а переносит в `.azrail-trash/<время>/` внутри той же папки | да |

Секреты (`.env`, ключи, `.git`, `node_modules`) закрыты для всех действий. Вернуть из корзины: скопировать файл из `.azrail-trash`.

## Терминал (шаг 3)

`local_shell {command, root?}` — любая команда в папке проекта (npm install, git, node, python…). Всегда ждёт «Разрешить»: владелец видит команду целиком. Таймаут 5 минут, вывод до 200 КБ, ключи `AZRAIL_*` дочернему процессу не передаются.

Заблокировано (и на сервере, и в агенте, правила в `src/lib/shell-guard.ts`): sudo/runas, `rm -rf` вне проекта, массовое удаление, диски, выключение, запуск скачанного кода, iex, скрытый powershell, реестр, `git push --force`, массовая смена прав, команды с `.env`/ключами/файлами агента, вывод переменных окружения, ssh/nc/ftp.

Важно: это страховка, а не песочница. Простую обфускацию она не поймает; главная защита — твоё «Разрешить». Не подтверждай команды, которых не понимаешь.

## Браузер на компьютере (шаг 4)

Агент держит одно живое окно браузера (твой профиль и входы, закрывается через 5 минут простоя).

| Инструмент | Действия | «Разрешить» |
|---|---|---|
| `local_browser` | `open` (публичный адрес), `snapshot`, `screenshot`, `scroll`, `close` | нет |
| `local_browser_act` | `click`, `type`, `press`, `upload` | да, на каждое |

- `snapshot` нумерует кнопки, ссылки и поля: `[3] кнопка «Опубликовать»`. Клик и ввод идут по номеру, не по произвольным селекторам.
- Пароли агент не вводит: войди сам через `Login-Sites.bat`.
- Загрузка файла только из твоих папок агента, секреты закрыты.
- Внутренние адреса закрыты, в том числе для редиректов и подзапросов. Скачивание файлов отключено.
- Скриншоты: папка `.azrail-shots` в папке проекта.
- Текст страниц — внешние данные, не инструкции.

## Режим доверия (шаг 5)

Настройки → Локальный агент → «Режим доверия»: выбери области и время (15, 30 или 60 минут).

| Область | Что выполняется без «Разрешить» |
|---|---|
| Файлы | запись, папка. Правка, перенос, переименование и корзина всегда спрашивают «Разрешить» |
| Браузер | клик, ввод, клавиша, загрузка файла |
| Терминал | команды (опасные всё равно блокируются) |

- Добавление и удаление папок (`addroot`, `droproot`) доверием не покрывается никогда.
- Доверие кончается само, при выключении агента и при новой сессии; не длиннее сессии агента.
- Миссия при доверии не встаёт на паузу: инструмент ждёт выполнения и сразу возвращает результат.
- Остановить: кнопка «Остановить доверие».
- Действует на все новые задачи: миссии, чат и ручные.

## Без настроек

- Привязанный компьютер включается сам, когда миссии нужен агент (до 20 секунд ждёт связи). Не привязан — один раз привяжи в настройках.
- Стандартные папки подключаются по слову: путь «Рабочий стол/проект», «Документы/…», «Загрузки/…» или `root: desktop`. Первый доступ — один «Разрешить» (задача `addroot`), дальше папка запоминается. Доверием это не пропускается.
- Любой инструмент агента может поставить миссию на паузу, если нужно подтверждение; после «Разрешить» миссия продолжается сама.

## Разрешения прямо в чате

Когда миссия ждёт агента, над полем ввода появляется карточка с вопросом и кнопками, как в Cursor:

| Действие | Кнопки |
|---|---|
| Доступ к папке | «Разрешить» (папка запоминается), «Отклонить» |
| Файлы (создание папок и запись файлов) | «Разрешить один раз», «Всегда для файлов», «Отклонить» |
| Терминал, браузер | «Разрешить один раз», «Разрешать … 30 мин», «Отклонить» |

«Всегда для файлов» живёт, пока агента не выключили; снять: «Отозвать «всегда»» в настройках агента. Терминал и браузер навсегда разрешить нельзя.

## Просьбы в чате

Фраза про компьютер («создай на рабочем столе папку…», «открой браузер», «удали файлы в загрузках», «запусти в терминале…») сама запускает миссию с инструментами агента. Нужно только, чтобы компьютер был привязан. Узкие команды («покажи файлы», «прочитай X», «git status») работают как раньше, мгновенно.

## Экран настроек

Сверху только нужное: статус, привязка компьютера (если ещё не привязан), список разрешённых папок с «Убрать», постоянное разрешение и ожидающие запросы. Всё инженерное свёрнуто в «Дополнительно»: включение и выключение, активная папка, ручные задачи и обзор файлов, добавление папки вручную, режим доверия, история задач, «Забыть компьютер».

## Правила агента и потолок шагов

- В промпте ядра есть блок «Задачи на компьютере владельца»: агент не отвечает «нет доступа», пишет пути как `Рабочий стол/…`, проверяет результат (`local_list`, код выхода), при ошибке меняет путь или способ до трёх попыток.
- Если агент хочет закончить после упавшего шага на компьютере, цикл возвращает его к работе (до двух раз за миссию).
- `local_status` принимает `jobId` или `id`.
- Шагов в миссии по умолчанию 20, максимум 30.

## Умный вход в чате

1. Явные фразы («создай на рабочем столе…») распознаются шаблонами мгновенно.
2. Если шаблон не узнал, но есть слабый признак (файл, папка, браузер, ютуб…) и компьютер привязан, один короткий вызов модели (`POST /api/agent/intent`) отвечает «да/нет». Ошибка модели = «нет», идёт обычный ответ.
3. Обычная беседа («привет») модель-классификатор не вызывает.
4. Сбой живого канала `/api/stream` пишется в лог как `stream.upgrade_failed` и отдаёт 503 с понятным текстом.

## Золотые задачи (CI)

`tests/golden-computer-tasks.test.ts` — 36 проверок без реальной модели и компьютера: маршрутизация фраз (миссия / быстрая команда / уточнение моделью / обычный чат), защита терминала, инструменты агента (что ждёт «Разрешить», что нет). Новая просьба, которая раньше не работала, добавляется строкой в таблицу.

## Видимый ход работы

Шаги миссии в чате называются по делу: «Создаю папку: Рабочий стол/demo», «Записываю файл: demo/a.txt», «Выполняю команду: npm test». Пока задача идёт, в строке видно последний шаг, раскрыв её — весь список с входом и результатом.

Список шагов раскрывается стрелкой прямо в сообщении (без шторки). Каждый шаг раскрывает «Запрос» (команда показана как код) и «Результат» или «Ошибку». Открытое состояние сохраняется при обновлении чата.

## Остановка задачи

Пока агент работает или ждёт «Разрешить» на карточке, кнопка отправки становится серой с белым квадратом, как в Claude: нажатие или Esc отменяет текущую задачу на сервере. Когда задача завершена, кнопка снова «Отправить».

## Живой ход

Пока агент работает, слева крутится значок, а в строке написано, что он делает прямо сейчас («Переношу: demo…»). Фиолетовый кружок есть всегда: крутится, пока агент работает, и стоит на месте, когда закончил (при ошибке красный). Рядом «N шагов»; галочки внутри списка — фиолетовые. Итог — ответ под строкой.

## Проверка результата фактами

Перед «готово» движок сам перечитывает результат мутаций на компьютере (`src/core/local-verify.ts`):

| Действие | Проверка |
|---|---|
| `local_mkdir` | папка есть в листинге родителя |
| `local_write` | `local_read` совпадает с записанным |
| `local_move` | источника нет, цель есть |
| `local_trash` | элемента нет в листинге родителя |

- Расхождение → агент получает замечание (2 попытки), затем задача `failed`: «Результат не подтверждён».
- Проверить нельзя (агент не ответил) → «Сделано, но не проверено» (`quality: unverified`), без ложного «готово».
- События: `local.verified`, `local.verify_failed`, `local.unverified`.

## Журнал «было → стало» и откат

Агент на компьютере пишет каждое изменение в `.azrail-trash/journal.jsonl` внутри подключённой папки: создание папки, запись, правка, перенос, корзина. Перед перезаписью и правкой копия файла лежит в `.azrail-trash/<время>/…`.

`local_undo {root, count?}` откатывает последние N неотменённых изменений, от свежих к старым. Всегда спрашивает «Разрешить» (в доверие не входит).

| Что было | Как откатывается |
|---|---|
| новая папка | убирается, если пустая; не пустую не трогает; существовавшую до задачи не удаляет |
| запись нового файла | файл уходит в корзину |
| запись поверх / правка | восстанавливается копия |
| перенос | возвращается на старое место (если оно свободно) |
| корзина | возвращается из копии (если место свободно) |

**Откат фразой.** «Отмени последние изменения на компьютере» / «верни как было на моём компьютере» запускает задачу, и агент зовёт `local_undo`. Папка берётся из последнего выполненного изменения. Фраза «откати правки на компьютере» по-прежнему откатывает цикл исправления кода, если он что-то менял в этом браузере.

## Обзор проекта

`local_overview {path?, root?}` — только чтение, без «Разрешить». Показывает признаки проекта (package.json, pyproject, Cargo, go.mod, Dockerfile, wrangler…), менеджер пакетов по lock-файлу (pnpm / yarn / bun / npm), установлены ли зависимости, готовые команды скриптов, начало README, папки и файлы. Агент обязан начинать работу с проектом с обзора и брать команды оттуда, а не угадывать.

## Что изменится — в карточке «Разрешить»

Для записи файла карточка показывает начало текста (до 500 символов), для правки — «было» и «стало» (до 300 символов каждое). Остальные действия описаны одной строкой. Поле `preview` приходит из `publicJob`.

## Диагноз ошибок

Ошибка локального инструмента (нет пути, занято, нет доступа, фрагмент не найден или не уникален, нет команды, не хватает зависимостей, порт занят, таймаут, агент не отвечает) получает в истории строку «Диагноз: …» с понятной причиной и следующим шагом (`src/core/local-diagnose.ts`). Нераспознанная ошибка остаётся как есть, диагноз не выдумывается.

## Поиск символов и цикл «правка → тест»

`local_symbols {name, path?, root?}` — только чтение. Находит, где функция, класс, тип или переменная определены, и где используются (js/ts, python, go, rust, java, kotlin, c#, ruby, php, swift, c/c++, vue, svelte; `node_modules`, `.git`, сборки пропускаются). Правило для модели: перед правкой кода — `local_symbols`; после правки — прогон тестов командой из `local_overview`; упали — исправить и повторить, пока не пройдут или не станет ясна причина.
