# AZRAIL 2.0 — архитектура

Документ версии 2.0.0. Исходная база: `1.5.0-rc.63`. Это чертёж развития, не отчёт о готовой системе 2.0.

Стратегия: достраивать текущий код. Новый каталог `src/intelligence/` и второй оркестратор не создаются, пока существующие модули закрывают ту же работу.

Рабочий сайт — воркер `azrail-pulse` (`wrangler.jsonc`, `src/unified.free.ts`). Учебная копия — `azrail-pulse-staging`. Файл `wrangler.production.json` описывает удалённый воркер и к выкладке не используется.

## Десять законов

1. Понятно без технического образования.
2. Способ выполнения выбирает ядро, не набор кнопок.
3. Один рабочий стол.
4. Агенты работают в выданных правах.
5. Нет зависимости от одной модели.
6. У функции есть проверяемый результат.
7. Проект, задача и результат держат контекст.
8. Инструмент выбирается под задачу.
9. Доступ, расход и внешнее изменение остаются под контролем.
10. Модуль добавляется так, чтобы уже работающее не ломалось.

Формула цели: один запрос → план → агенты и инструменты → выполнение → проверка → результат.

## Что развивать, а не копировать

- Память проекта: `src/lib/memory-agent.ts`. Это модуль над D1, не второй Durable Object.
- Выбор модели: `src/lib/model-router.ts`. Он объясняет выбор и не выдумывает рейтинг.
- Граф миссии: `src/lib/mission-graph.ts` уже проверяет зависимости, цикл и параллельные группы. Живой снимок Metatron пока строит рёбра из порядка шагов и прямо пишет `derived-linear`.
- Полоса поручения в чате остаётся пользовательским путём. Её не заменяют новым планировщиком с теми же кнопками.
- Студии из манифеста не дублируются студиями Architecture, Development, Creative и Market. Эти имена есть в старом дереве `references/legacy` и в рабочий манифест не входят.

## Порядок пакетов

1. Опора: этот аудит, сверка зависимостей, известные блокеры, запасная копия. Удалённых записей нет.
2. Ядро: намерение, контекст, решение и память через текущие модули.
3. Metatron 2.0: явный DAG вместо `derived-linear`, без потери Start, Pause, Resume, Cancel, Terminate, checkpoints и fencing.
4. Модели и инструменты.
5. Исполнение в изолированной среде.
6. Общий стол студий.
7. Сертификация выпуска.

Пакет 4 и дальше не начинаются, пока предыдущий пакет не сохраняет уже работающий `1.5.0-rc.63`.

Смежные документы: матрица переноса, матрица способностей, модель безопасности, модель данных, дорожная карта, критерии приёмки.
