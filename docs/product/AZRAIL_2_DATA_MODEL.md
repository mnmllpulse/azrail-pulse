# AZRAIL 2.0 — модель данных

Схема растёт только добавлением. Старые файлы миграций не переписываются задним числом. В этом проходе новые таблицы не предлагаются и не создаются.

Рабочая база воркера `azrail-pulse` — D1 `azrail-pulse-db`. Учебная база — отдельная. Старую базу удалённого воркера не мигрировать и не восстанавливать этим сценарием. Закладку восстановления в документ не копировать.

## Уже лежащие миграции

Каталог `migrations/` содержит файлы `002`–`037`, без сплошной нумерации на каждый номер. Среди них: миссии, безопасность, платформа, политика моделей, единый контур, черновики коннекторов, восстановление, веб-верстак, студии картинки, музыки, видео, данных, Ableton, Ledger, Pulse Lab, связи, события, проекты, разговоры.

Миграция `034-metatron-lab-2.sql` есть в дереве и к рабочей D1 не применялась. Пока она не применена отдельным разрешением, граф Metatron остаётся производным от порядка шагов.

## Домены, которые уже имеют место

| Домен | Где лежит смысл | Что не делать |
|---|---|---|
| Разговор | `conversations`, `messages` | План поручения — строка `messages` с ролью `plan`. Новую колонку под план не заводить |
| Проект | центр проектов, верстак, артефакты R2 | Случайный UUID проекта доступен владельцу. Чужой ресурс проверяется |
| Миссия | `missions`, шаги, checkpoints, журнал решений | Явный DAG хранить развитием этих записей, не второй таблицей-копией |
| Память | факты проекта и `mission_memory_reads` | Секреты, пароли и ключи в факты не писать |
| Учёт | квоты, бюджеты, Ledger | Остаток читается отдельным запросом без увеличения счётчика |
| Страница | KV, ключ публикации на 90 дней | Это не отдельная база сайтов |
| Модели | реестр в коде и политика вызова | Платная модель в каталоге не становится строкой разрешения |

## События

Журнал миссии и цепочка целостности событий уже есть (`018`, `019`, `030`). Имена вроде `mission.created` и `agent.failed` из сценария 2.0 — целевой словарь. Подменять им текущие записанные события без версии схемы нельзя. Повторяемый потребитель и очередь недоставленных писем для этого словаря ещё не построены.

## Артефакт

Картинка, звук и файл проекта уже получают идентификатор и адрес хранения. Полный паспорт из владельца, версии, происхождения и статуса проверки для всякого результата ещё не общий контракт. Пока его нет, студия не должна рисовать недостающие поля.

## План поручения

Клиент хранит у части вещи адрес, подписи, варианты, до трёх прошлых версий и семя картинки. Неизвестные поля схема срезает. Новое поле вещи добавляется в схему `planThingSchema`, иначе оно исчезнет при сохранении.
