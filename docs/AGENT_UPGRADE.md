# AZRAIL Local Agent — единый сценарий развития

Объединяет два исходных ТЗ («Professional Coding Agent Upgrade» и «Reliability & Intelligence Upgrade»). Цель одна: пользователь ставит задачу обычным языком, AZRAIL сам доводит её до **проверенного** результата на компьютере владельца.

## Правила работы

- Не создавать нового агента и не переписывать архитектуру без доказанной необходимости.
- Не менять публичные API-контракты; не удалять возможности.
- Безопасность не ослабляется: проверка рабочей области, защита секретов, symlink, shell-guard, серверные права, подтверждение опасного.
- Каждая проблема подтверждена кодом, тестом или записью в D1; «готово» только после реальной проверки.
- Один PR за раз, небольшие этапы; merge делает владелец.

## План

**P0 Надёжность**
1. Детерминированная проверка результата `local_*` перед «готово»: запись → чтение, папка → листинг, перенос → исходник отсутствует, цель есть; без подтверждения — не «готово».
2. Нет ложного успеха: если проверка недоступна, итог помечается «не проверено».

**P1 Стабильность**
3. Разделить статусы «ждёт ответа владельца» и «ждёт разрешения».
4. Метаданные реестра: категория, timeout, лимит вывода, стратегия проверки.
5. Обзор локального проекта (`local_overview`): структура, манифест, scripts, менеджер пакетов.
6. Терминал: `local_scripts` (scripts из `package.json`), выбор менеджера, exit code в результате.
7. Восстановление: `local_restore` из `.azrail-trash`, журнал «было → стало» и кнопка «Отменить последнюю задачу».

**P2 UX**
8. Живой ход: крутится кружок, пишется текущее действие; в конце — итог.
9. Диагностика (очередь, runtime, журнал) отдельным разделом «Для разработчика».
10. Просмотр diff в карточке разрешения.

**P3 Расширения**
11. Поиск символов и ссылок; цикл «правка → тест → исправление»; параллельные чтения; готовые навыки (YouTube); субагенты.

## Тесты (сценарии A–I)

A исправление ошибки · B несколько связанных файлов · C команда проекта · D сбой инструмента и вторая попытка · E отказ владельца (безопасная часть продолжается) · F обрыв связи и продолжение · G другая рабочая папка и границы · H нет ложного успеха · I обычный язык. Покрыто частично (`golden-computer-tasks`, `local-agent-e2e`, `approval-resume`); недостающие добавляются вместе с P0/P1.

## Критерии готовности

Типовые задачи распознаются; выбор инструментов обоснован; миссии выполняются последовательно; контекст сохраняется; разрешения не обходятся; результат проверен; ложные «готово» исключены; настройки понятны; API совместимы; критические тесты зелёные. Без реальных проверок «production-ready» не заявляется.
