# Качество и защита выкладки AZRAIL PULSE

Status: current (22.11.2026)

## Что проверяется в каждом PR (задание `check` в `.github/workflows/check.yml`)

| Шаг | Что проверяет |
|---|---|
| Свежий снимок облака | При наличии секрета `CLOUDFLARE_API_TOKEN` (только чтение) снимок делается заново; в логе строка `SNAPSHOT MODE live` или `repo` |
| `dependency:audit` | Уязвимости в зависимостях |
| `source:manifest:check`, `repo:exhaustive`, `repo:hygiene` | Целостность исходников и репозитория |
| `quality:static` | 59 статических проверок (безопасность, дрейф облака, свежесть снимка) |
| `node24:suite` | Тесты (2226), подготовка staging, безопасность, релиз |
| `ui:smoke` | Интерфейс в Chromium: гость и вход × 1440/820/390 px и 12 разделов настроек; ошибки JS, горизонтальный скролл, axe WCAG A/AA, цели касания ≥44px на телефоне |

## Что защищено

- Ветка `main`: слить можно только при зелёном `check`; удаление и принудительная перезапись запрещены (набор правил GitHub).
- Prod собирается из `main` Cloudflare Workers Builds после слияния; staging выкладывается автоматически после зелёной проверки.
- Токен автоснимка только на чтение, лежит секретом репозитория. Токен деплоя лежит отдельно, в окружении `staging`.

## Известные особенности

- Сборка пробной ветки в Cloudflare («Workers Builds» на PR) показывает красный крестик на всех PR-ветках; на `main` зелёная. На слияние не влияет.
- Один тест (`tests/ui-workflow.test.ts`, восстановление миссии) однажды завис в облаке на 120 с; повторный запуск проходит. Если повторится, лечить таймаутом и повтором в самом тесте.
- Светлой темы нет сознательно: бренд Dark Premium.

## Что осталось

- `ui/app.ts` (около 1970 строк) и `src/index.ts` (около 1670 строк) всё ещё большие; страница настроек уже вынесена.
- `model_prices` заполнять только проверенными тарифами.
- Замер скорости на реальном устройстве и нагрузочный прогон не делались.
- Экраны студий (картинки, музыка, веб, видео) автотестом не охвачены.
